## 3. 内存（RAM）、栈水位与程序存储（Flash）对比

> 说明：以下 ELF 段与符号统计直接由 `arm-none-eabi-size -A` 与 `arm-none-eabi-nm -S`（字节级区间去重防别名重复计费）从三份已构建 `.elf` 提取。

### 3.1 总体存储开销对照

| 指标 | E2E-01 (`f32 -O2`) | E2E-02A (`f32-opt -O3`) | E2E-02B (`q31-opt -O3`) | E2E-02C (`m4f_static -O3`) |
|---|---:|---:|---:|---:|
| **算法静态 RAM (`.bss` `g_state`)** | 26,556 B (25.93 KiB) | 26,280 B (25.66 KiB) | **26,416 B (25.80 KiB)** | 26,280 B (25.66 KiB) |
| **实测栈高水位 (Stack HWM)** | 2,192 B (2.14 KiB) | 9,088 B (8.88 KiB)* | **1,528 B (1.49 KiB)** | — (未上板实测) |
| **算法峰值 RAM (静态 + 栈)** | 28,748 B (28.07 KiB) | 35,368 B (34.54 KiB)* | **27,944 B (27.29 KiB)** | — |
| 测试桩 `.mailbox` + `.data` | 4,216 B | 4,216 B (`.data=80 B`) | **4,136 B (`.data=0 B`)** | 4,216 B (`.data=80 B`) |
| **烧录固件总 SRAM 占用** | 32,964 B (32.19 KiB) | 39,584 B (38.66 KiB)* | **32,080 B (31.33 KiB)** | — |
| **总固件 Flash (`.isr+.text+.exidx+.data`)** | 22,771 B (22.24 KiB) | 27,408 B (26.77 KiB) | 27,768 B (27.12 KiB) | **24,292 B (23.72 KiB)** |

*工程根因透明说明*：
1. **`E2E-02A (f32_opt)` 实测栈高水位为 `9,088 B`**：`dspit_f32opt.c` 保留了未加条件编译宏保护的宿主 `double` trace 局部缓冲数组，且 `-O3` 将辅助函数内联进 `dspit_push_block` 时在栈帧中为其分配空间（即便 MCU 运行时 `trace_cb == NULL` 从不写入）；`dspit_q31opt.c` 将上述缓冲放入 `#ifdef DSPIT_ENABLE_TRACE` 后，实测栈高水位直接降至 **`1,528 B`**（低于 `E2E-01` 的 `2,192 B`）。若 `f32_opt` 后续添加同一编译宏保护，其栈占用同样可显著下降。
2. **`E2E-02B (q31_opt)` 的 Flash 库符号边界**：`fw_q31_opt.elf` 彻底消除了全部 `libm` 超越函数（`sqrtf`、`expf`、`logf`、`roundf`、`__ieee754_*`、`__aeabi_fdiv` 均为 `0`），使 `.data` 从 `80 B`（`libc` `_impure_data/_impure_ptr`）降为 **`0 B`**。Flash 中仍链接少量 `libgcc` 软浮点辅助函数（属于 `Shared_libm_libgcc_libc` `3,466 B`），仅服务于两个边界：一是 SWD 宿主邮箱入口/出口 `float32 <-> Q11.20/Q3.28/Q15.16` 标量转换（`dspit_push_block`）；二是 `push_25hz_q20` 中未加 `DSPIT_ENABLE_TRACE` 的 `if (tcb && tcb->on_x25)` 分支（MCU 运行传入 `trace_cb == NULL`，该分支 `0` 次执行）。全部核心 S1–S6 DSP 阶段均以纯 32/64 位整数定点运算完成。
3. **`E2E-02A/B` 总 Flash 较 `E2E-01` 增加约 4.6–5.0 kB**：主要源自 `-O3` 对剪枝 4×256 FFT、对称抽头展开及协调器函数的激进内联，同时 `DALIA_SYM_H/OFF` 增加 `204 B` 常量表；而在 `fw_m4f.elf` 中借助硬件 VFP 指令直接消除了大部分软浮点运算序列，总 Flash 回落至 `24,292 B`。

## 5. 抓手 4：Cortex-M4F 硬件浮点静态交叉编译核验（`E2E-02C`）

对同一套优化浮点源码 `src_f32_opt/` 使用 `-mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard -mthumb -O3 -fno-math-errno` 编译生成 `fw/fw_m4f.elf`，经 `arm-none-eabi-objdump` 与 `arm-none-eabi-nm` 静态验证（见 [results/m4f_static_check.txt](results/m4f_static_check.txt)）：
- 镜像节区总计：`.isr_vector = 64 B`，`.text = 24,148 B`，`.data = 80 B`，`.bss = 26,280 B`，`.mailbox = 4,136 B`（总 Flash `24,292 B`，较无 FPU 的 `f32_opt` 减少 `3,116 B`）。
- 反汇编共检出 **317 条**硬件单精度 VFP 算术指令（`vadd.f32: 109`、`vmul.f32: 98`、`vsub.f32: 71`、`vfma.f32: 17`、`vdiv.f32: 17`、`vsqrt.f32: 5`）。
- 符号表内软浮点加减乘除符号 `__aeabi_fadd/sub/mul/div` 计数为 **`0`**（仅保留 `libm` 超越函数 `expf/logf` 及测试边界辅助函数 `2,344 B`）。
- **明确声明**：以上仅证实在 Cortex-M4F 工具链下成功下沉为硬件单精度 FPU 指令，**未**进行 Cortex-M4F 开发板运行时实测，禁止外推为真机实测耗时。
